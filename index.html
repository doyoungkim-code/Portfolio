PROJECT 01 — SSABREE TIME

에브리타임을 벤치마킹해 기획하고, 원스토어 · 앱스토어에 실제 출시해 1주 만에 100명 이상의 유저를 확보했습니다. AWS EC2에 배포해 지금도 운영 중입니다.

회고 블로그 보기 →
01인증/인가

JWT Access(30분)+Refresh(1년) 이중 토큰, SSAFY Mattermost 연동 본인 인증, Spring Security 필터 체인.

02게시판 + 캐싱

CRUD · 좋아요 · 스크랩 · 투표, 커서 기반 페이지네이션, HOT 게시판(Redis 3분 TTL), 인기 검색어(Sorted Set).

03실시간 채팅

WebSocket STOMP 채팅 서버, 핸들러 레벨 JWT 검증, Nginx WebSocket 프록시.

04팀/스터디 매칭

생성→모집→운영→종료 생명주기 API, 지원/수락/거절, Task 관리.

05FCM 푸시

Firebase Admin SDK 연동, 이벤트별 푸시, @Async 비동기 전송.

06DB 설계 (공동)

ERD 1~3차 반복(15+ 엔티티), 댓글 Soft Delete(트리 보존), 포트폴리오 CRUD · solved.ac 연동.

—PostgreSQL

게시글-댓글-좋아요-투표의 복잡한 JOIN 최적화, 대댓글 CTE 재귀 쿼리, JSON 타입 확장성.

—Redis

매 요청 집계가 부담인 HOT 게시판을 3분 TTL 캐시로, 인기 검색어를 Sorted Set으로.

—WebSocket STOMP

Polling 대비 서버 부하 감소, 토픽 기반 구독/발행, SockJS 폴백.

Jackson 3 + Redis 직렬화 연쇄 장애

문제Spring Boot 4.0이 Jackson 3을 강제하면서 패키지 변경으로 Redis 직렬화 설정이 전부 깨짐.

해결GenericJackson3JsonRedisSerializer로 전환, @class 필드로 타입 정보를 보존해 역직렬화 실패 제거.

회원탈퇴 Side Effect — 4일의 추적

문제Hard Delete 후 FK 제약조건의 연쇄 오류가 서비스 곳곳에서 발생.

해결Soft Delete(deletedAt) 전환, 리더 탈퇴 시 null 처리 + 경고, 게시물은 "탈퇴한 사용자"로 표시. 삭제 정책은 UX와 무결성 양면의 설계임을 체득.

클라이언트 3팀과의 스펙 협업

문제Android · iOS 클라이언트와의 API 스펙이 3~5차례 반복 수정됨.

해결Req/Res body 상세 명세 + Swagger 문서화 체계를 잡아 1차 리뷰 80% 이상 통과로 개선.

PROJECT 02 — 번역의 민족

팀장으로서 6인 팀을 이끌며, 17GB AI 모델을 품은 데스크톱 앱을 "비개발자가 설치할 수 있는 물건"으로 만드는 일을 맡았습니다.

01팀장 리딩

AI · Frontend · Backend가 만나는 통합 지점(배포 · 일정 · 역할 분담)을 조율하고 최종 책임.

02Electron 배포 파이프라인

PyInstaller → electron-builder → Inno Setup 3단계 패키징. 강의실 PC를 고려한 관리자 권한 없는 per-user 설치, 디스크 용량 사전 체크.

03설치 · 모델 다운로드 플로우

대용량 AI 모델의 다운로드 · 설치 과정을 비개발자도 통과할 수 있는 사용자 플로우로 설계 · 구현.

04FastAPI 백엔드

Python FastAPI 기반 서버 API 일부 구현.

17GB짜리 설치 파일이라는 문제

문제AI 모델을 포함한 앱을 강사(비개발자)가 스스로 설치할 수 있어야 함. 거대한 빌드 용량과 설치 대상 PC의 권한 · 디스크 제약이 겹침.

해결3단계 패키징 파이프라인으로 빌드를 구조화하고, per-user 설치로 관리자 권한 의존을 제거, 설치 전 디스크 용량을 사전 체크해 실패를 예방. "배포까지가 제품"임을 배웠습니다.
